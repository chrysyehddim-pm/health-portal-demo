# GO HEALTH Prototype

## 頁面入口

- `index.html`：GO HEALTH 首頁（Vercel 預設入口）
- `app-entry.html`：HAPPY GO APP 入口模擬，點選「健康挑戰」進入首次授權頁
- `terms.html`：首次授權／同意頁
- `group.html`：群組頁
- `records.html`：P1.5 我的動腦紀錄，可切換四個互動項目查看近期完成時間、Level 與同齡 PR
- `records.html?stage=p16`：在相同紀錄頁加入下一階段「我的健康徽章」，首頁預覽 2 枚並可展開查看全部 8 枚
- `exchange.html`：健康點兌換 HAPPY GO 點數流程 Demo
- `points-history.html`：三個月內最新 100 筆累點與成功兌點紀錄整合頁
- `exchange-history.html`：舊網址相容轉址，會導向健康點紀錄
- `error-simulator.html`：錯誤情境模擬

## 群組狀態測試

- `group.html`：一般群組狀態
- `group.html?state=empty`：近期無參與賺點任務狀態

## 部署說明

本資料夾可直接放在 Vercel 專案根目錄。CSS、JavaScript 與圖片的相對路徑已依目前資料夾結構設定。

`家事達人`尚未提供正式挑戰網址，目前點擊時會顯示「連結待設定」。取得網址後，請在 `index.html` 更新該卡片的 `href` 並移除提示事件。`健康小學堂`已連結至 <https://go-health-school-prototype.vercel.app/>，為每日任務，每日限領一次 50 健康點；首頁卡片不顯示限領說明。

亞東醫院 LINE 官方帳號已設定為：<https://page.line.me/769uaenm>。首頁點擊「加入好友」會在新視窗開啟正式 LINE 頁面。

健康點兌換 Demo 的餘額、匯率與限時點數效期集中設定於 `assets/data.js` 的 `exchange` 區塊。目前假設為：500 健康點兌換 1 點、最低兌換 1 點、整數兌換、餘數保留、立即入點、成功後不可取消、入點失敗不扣健康點。

健康點累積範例集中設定於 `assets/data.js` 的 `pointHistory`，成功兌換紀錄則位於 `exchangeHistory`；`points-history.html` 會依時間整合顯示，不呈現失敗、處理中或到期項目。健康點依取得年度分批計算效期，兌換時優先扣除最早到期批次。HAPPY GO 限時點數效期為入點後 90 天。

首頁公告文字與輪播參數集中設定於 `assets/data.js` 的 `announcement` 區塊：`messages` 管理公告內容，`pixelsPerSecond` 控制移動速度，`pauseMilliseconds` 控制每輪開始前停留時間，`messageGapPixels` 控制兩輪文字間距。使用者開啟「減少動態效果」時，公告將停止自動輪播並可手動橫向查看。

動腦紀錄 Prototype 的本月總覽、互動項目清單、近期完成紀錄、同齡 PR 與徽章集中設定於 `assets/data.js` 的 `brainRecords` 區塊；目前皆為展示用假資料，不串接 API。

同齡 PR 以相同互動項目、相同 Level、相同年齡區間為比較條件，近 90 天每位會員只取一筆個人最佳完成時間；同秒數採中間排名，公式為 `(較慢人數 + 0.5 × 同秒數人數) ÷ 比較人數 × 100`。Prototype 設定至少 30 位有效參考會員才顯示 PR，個人紀錄可即時更新，同齡母體預計每日批次更新一次。會員畫面不顯示參考人數與公式。

正式實作時，年齡應以會員輪廓 DOB 在批次日重新計算，不採用遊戲事件內可能變動的 `age`。年齡區間固定為 `<35`、`35–44`、`45–54`、`55–64`、`65–74`、`75+`；母體僅納入成功完成且秒數有效的紀錄，比較人數排除本人。每日批次使用執行當下往前 90 天的滾動視窗，而非每 90 天才執行一次；若 DOB 缺失、查無同 Level 個人最佳或有效母體少於 30 人，回傳「參考資料累積中」，不跨年齡層合併。

徽章情境沿用同一份 HTML 與 JavaScript，透過 `stage=p16` 網址參數隱藏切換，會員畫面不提供切換按鈕，避免維護兩份重複頁面。紀錄頁只預覽「最近取得」與「最接近完成」各 1 枚；若沒有符合項目，依資料順序補足 2 枚。「查看全部」以彈出視窗呈現 8 枚徽章，點選後可再查看取得方式與進度。

P1.6 Prototype 的 8 枚徽章規則如下，所有徽章取得後皆永久保留、不因離開群組或後續資料變動而收回：

- `健康初體驗`：首次成功完成任一指定健康任務，包含新手問卷與 AD2。
- `健康探險家`：首次完成當期所有指定核心健康任務。正式開發應使用有版本的任務 ID 白名單判定，後續新增任務不回溯影響已取得資格。
- `健康有約`：同一曆月內於 7 個不同日期完成有效任務；同日多次只計 1 天。未取得前每月 1 日重算當月進度，達第 7 天時立即頒發，不回溯徽章上線前的歷史月份。
- `健康小樹`：累積 10、30、100 次有效任務時依序升級同一枚徽章，達成層級只升不降；卡片數字與造型隨目前最高層級切換。
- `健康同行`：成功邀請至少 1 位其他會員加入群組，頒給邀請人。
- `陪伴不間斷`：連續 4 個完整週次，每週至少 2 位群組成員各完成 1 次有效互動；每週可以是不同成員，以週一至週日為一個週次，週結束後批次判定。
- `千點同心`：群組單一週次的已結算健康點首次達 1,000 點；週結算當下仍在群組的成員取得，後加入者不補發。
- `愛的傳遞`：首次成功傳送關心訊息給其他群組成員，頒給傳送者；排除傳給自己與傳送失敗事件。

群組徽章的觸發事件應保存 `badge_id`、`rule_version`、`earned_at`、`member_id` 與來源群組，避免每次開頁重新掃描全部歷史資料。設計確認後，交付開發前應再建立乾淨版本：依最終範圍固定是否顯示徽章，並移除 `stage` 情境判斷，不應要求接手者自行刪除不明程式片段。

公告在一般模式下固定輪播，不再依裝置寬度自動停用；若完全不移動，請先確認裝置或瀏覽器是否開啟「減少動態效果」。
